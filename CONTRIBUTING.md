# Contributing

Work from a task brief with owned files and acceptance criteria. Read the decision register first. Create a branch, make one coherent change, update tests and documentation, and attach verification evidence.

Do not combine unrelated refactors, install speculative dependencies, expose secrets, use production inquiry data, change public claims without evidence, or alter both design systems for convenience. Every visible change needs mobile, keyboard, reduced-motion, and content review.

Commit messages should state the user-facing outcome. Pull requests must list scope, exclusions, screenshots, commands, test results, security/privacy impact, performance impact, migration needs, and rollback.
